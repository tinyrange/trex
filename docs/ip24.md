# SGI Indy emulator

`emulator.ip24()` models an Indy with a big-endian R4400,
64 MiB RAM, the MC memory controller, IOC2 interrupts and serial port,
and HPC3 descriptor DMA for the WD33C93 SCSI controller. It uses
the R4400 paired TLB and MIPS III integer instructions for the
original IRIX kernel and n32 userland. The serial byte channel is
connected to `ttyd1`.

`emulator.ip24(newport=True)` fits the XL24 Newport board. It models
REX3 raster commands, indexed and direct color scanout, the VC2 cursor,
retrace interrupts, and transfers over the memory controller's graphics
DMA engine. The IOC2 supplies PS/2 keyboard and mouse input.

The installed-system smoke accepts a caller-supplied uncompressed CHD v5
image with an installed IRIX system. Trex opens the CHD hunk map and SGI partition table,
then reads the original `/unix` from the XFS root. It enters the kernel
through built-in ARCS32 services and boots to a single-user root shell.
The tested guest reports `6.5.22f 10070055 IP22`.
Both runs place guest writes in a private memory overlay. Each overlay
can cover its virtual disk and allocates chunks as the guest writes.
An optional 512 KiB PROM supplies the read-only ROM aperture.

### Installed disk layout

The desktop recipe attaches the supplied disk as SCSI target 1. The
reference disk is 2,000 MiB with 512-byte sectors. Trex
reads its existing SGI volume label and uses its XFS reader to locate
`/unix` and `/sbin/init`. The guest's own XFS driver mounts and writes
the root filesystem through the sparse 64 KiB-chunk memory overlay.

| SGI partition | Start sector | Length in sectors | Contents |
| --- | ---: | ---: | --- |
| 8 | 0 | 4,096 | Volume header with `sash` and `ide` |
| 1 | 4,096 | 262,144 | Swap |
| 0 | 266,240 | 3,829,760 | Installed XFS root |
| 10 | 0 | 4,096,000 | Whole disk |

Run these from the Trex directory. The arguments are the archived disk
or Overlay 1 CD and, optionally, the original Indy PROM.

```sh
go run ./cmd/trex scripts/smoke/irix_ip24.star system \
  INSTALLED_IRIX.chd
```

The Overlay 1 smoke reads the stock IP22 kernel from the CD's EFS
partition and its original XFS miniroot from the SGI boot directory.
It places the miniroot on a generated SGI disk, then enters its shell
from the installer prompt. Both modes type `uname -aR` on the serial
port and verify the guest's release. The miniroot reports
`6.5.22m 10070055 IP22`.

```sh
go run ./cmd/trex scripts/smoke/irix_ip24.star miniroot \
  OVERLAY1.7z
```

For interactive Starlark sessions, the smoke script exports
`prepare(source, mode, rom=None, newport=False, single_user=True)`.
It returns the Indy and its observed
disk overlay. Advance the machine with `machine.run(cycles)` and use
`machine.serial()` to read output and write input. Close the machine
when the session ends.

## Constructing the system from installation CDs

`scripts/smoke/irix_ip24_system.star` constructs an Indy disk directly from
the two IRIX 6.5 Foundation discs and the three 6.5.22 maintenance overlays.
The recipe selects files for a 32-bit R4000 with Newport graphics using the
original product descriptors and IDBs. It applies the Foundation files
first and replaces the paths supplied by the overlays. The installation
resolves ancestor aliases such as `/usr/adm` to their physical directories.

Go builds the XFS v4 root from those entries and adds a fresh volume header
containing SGI's `sash` and `ide` plus 128 MiB of swap. The recipe uses the
unmodified IP22 kernel from Overlay 1. Its boot configuration uses XFS on
partition 1 and swap on partition 0. Console devices, the hardware-graph
aliases, and `/etc/fstab` are supplied during construction. The stock
swap script runs at the start of multiuser startup, after the device graph
is mounted and before the other services need swap.
The disk and its writable overlay remain in memory through the emulator
smoke.

Run the smoke from the Trex directory.

```sh
go run ./cmd/trex scripts/smoke/irix_ip24_system.star \
  FOUNDATION1.7z FOUNDATION2.7z OVERLAY1.7z OVERLAY2.7z OVERLAY3.7z \
  irix-6.5.22m-desktop.png
```

The smoke checks that partition 1 mounts read-write as XFS, the terminal
reports `6.5.22m`, Toolchest maps, and Calculator displays `5` after
`2 + 3`. The screenshot captures the Calculator and the terminal's
release and root-device output.

The recipe exposes the two install plans for inspection. A full reproduction
of `inst` still needs native generation of the software history database,
remaining package hooks, and workstation-specific kernel linking. The smoke
enters the distribution kernel directly through ARCS32 and starts the
desktop from the maintenance shell. [SGI installation guide](https://techpubs.jurassic.nl/library/manuals/1000/007-1364-090/pdf/007-1364-090.pdf)

## Interactive browser desktop

Run from the Trex directory. Pass the same five installation archives as the
construction smoke, followed by the IRIX 6.5 Applications November 2003 CD.
The build installs the Applications disc's Desktop Environment, Desktop
Tools, and System Administration Desktop products before applying the
maintenance overlays. IRIX starts its own display manager during multiuser
boot, immediately after networking, swap, and temporary directory setup.
The standard login scripts open the Interactive Desktop. The image includes
the `/dev/mmem` timer device used by SGI's visual greeter.

```sh
go run ./cmd/trex -serve 127.0.0.1:8091 scripts/run/irix_desktop.star \
  FOUNDATION1.7z FOUNDATION2.7z OVERLAY1.7z OVERLAY2.7z OVERLAY3.7z APPLICATIONS.7z
```

Pass a single installed CHD to boot a 6.5.22f system.
Open the full session URL printed by the server, including its fragment.
The guest continues booting before the graphical login appears. Click the
display to capture the mouse, and press Esc to release it. The guest stays
running across browser disconnects. Stopping the server discards the guest's
writable disk overlay. One browser controls the guest at a time.

The six-disc browser smoke signed in as `guest` at SGI's visual login.
Toolchest and Icon Catalog rendered, and browser keyboard and mouse input
opened `/usr/people/guest` in File Manager.

## Graphical desktop

The desktop smoke starts stock Xsgi on display `:0`, 4Dwm, and Toolchest
from the archived installed system's maintenance shell. It enables guest
loopback and uses the emulated keyboard and mouse. The PNG captures
Calculator showing `5` after `2 + 3`, the terminal reporting IRIX
6.5.22f, Xedit displaying the installed `/etc/fstab`, the Clock date,
Font Selector's glyph sample, and Toolchest.

```sh
go run ./cmd/trex scripts/smoke/irix_ip24_desktop.star \
  INSTALLED_IRIX.chd \
  irix-indy-desktop.png
```

Append a mode after the PNG path for another fresh-boot smoke. These
checks expect the listed applications and sample files to be present
on the supplied image.

| Mode | Guest actions and expected output |
| --- | --- |
| `image` | ImageView draws the complete archived `TestPattern.rgb`. X Logo draws its geometry. Xmessage displays its text and closes when Okay is clicked. |
| `movie` | Media Player opens `sampleQT.mov`. The smoke verifies the first frame, clicks Play, and checks that both the frame and the playback timer advance. |
| `files` | The stock local services and File Manager initialize the desktop icons. A double-click on UnixRoot opens the root directory, and Icon Catalog shows the installed application entries. |
| `browser` | Netscape opens the archived SGI documentation index, follows the End-User link, and renders the bookshelf. |
| `fsn` | SGI File System Navigator renders `/usr/share/data` as a 3D filesystem. The smoke searches for `images`, clicks the matching pedestal, and verifies the selected directory and `TestPattern.rgb` in the zoomed scene. |

The `fsn` mode reads SGI's original ELF `fsn.tar.Z` distribution and
verifies its digest. The Go builders construct an EFS filesystem in
memory from the five archive entries and place it at sector 64 in
partition 0 of a generated SGI disk. The guest mounts that disk
read-only at `/mnt` as SCSI target 2 and starts `portmap` and `inetd`
for its File Alteration Monitor. The 3D scene shows the files under
`/usr/share/data` on the installed XFS root. Append a local `fsn.tar.Z`
path after `fsn` to use a local copy of the same release. For an
interactive session, `start_fsn(source, distribution=None)` returns the
machine and serial console with the original app running. [SGI distribution archive](https://ftp.zx.net.nz/pub/archive/ftp.sgi.com/sgi/fsn/)

Opening files in `fsn` uses its embedded file-typing interpreter, which
loads `/usr/lib/filetype/workspace.ctr`. The installed 6.5.22f disk
ships `desktop.otr`. On that disk, `fsn` reports `unknown type` when
opening `TestPattern.rgb`. The 6.5 `filetype` utility recognizes the
same file as `SGIImage` and reports the ImageView action. [SGI file-type transition notes](https://techpubs.jurassic.nl/library/manuals/1000/007-1633-070/sgi_html/apd.html)

In the compatibility test, the IRIX 4.0.4B `eoe2.sw` catalog supplied
the original compiled `workspace.ctr`. TinyRangeX read it from the
archived distribution and added it to the generated EFS disk. A symlink
in the guest's private XFS overlay exposed it at the expected path.
After relaunching, `fsn` classified `TestPattern.rgb` as an SGI image
and opened it in ImageView. The full 320×240 RGB output matched the
direct ImageView smoke. The standard `fsn` smoke stages the five files
from the ELF distribution and verifies browsing and search.

The desktop script also exports `start_desktop(source)` for interactive
use. `machine.key(key, down=True)` sends a physical key event.
`machine.mouse(dx, dy, buttons=0)` moves right and up for positive
deltas. Bits 0, 1, and 2 represent left, right, and middle buttons.
`machine.screenshot()` returns the 1280×1024 scanout as PNG.
`machine.read_pixel(x, y)` reads raw main and auxiliary video memory.
`machine.run(budget, exception_codes=[6, 7])` stops at instruction
or data bus errors.

The archived system's normal startup completed XFS recovery and kernel
reconfiguration, entered standalone network mode, and reached runlevel 2
with SGI's visual login. Audio, Ethernet traffic, and reset-to-disk PROM
boot remain open.
The direct ARCS entry currently leaves sash's `Kernname` unset, so IRIX
skips dynamic kernel module registration.
