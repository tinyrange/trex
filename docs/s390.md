# ESA/390 system emulator

`emulator.s390()` creates an in-process ESA/390 machine: CPU, storage with
keys and prefixing, dynamic address translation, channel subsystem, 3390 DASD,
3270 display stations and START INTERPRETIVE EXECUTION. It is implemented in
Go from the architecture (Principles of Operation, SA22-7201, and the 3990/3390
and 3270 reference material); no emulator source was consulted. The core has no
host file, process or socket dependencies.

It is complete enough to IPL a hypervisor that runs its own guests: an
operating system can IPL from a CKD volume, initialize its I/O configuration,
page and spool to DASD, and run ESA/390-mode virtual machines under SIE. It
also runs 31-bit Linux for S/390 from a storage load with the hardware system
console:

```
go run ./cmd/trex scripts/smoke/linux_s390.star OUT
```

boots the pinned Debian 5.0 (lenny) `linux-image-2.6.26-2-s390` kernel with a
natively built BusyBox initramfs (`scripts/images/debian_s390.star`) to a shell
in about a second and 30 million instructions, and writes `OUT.png` and
`OUT.txt`. `scripts/smoke/linux_s390_dasd.star` boots the same kernel with
its root file system on an emulated 3390: `m.dasd(0x200, ldl = image,
cylinders = 100)` presents a volume in the Linux disk layout (an LNX1 label in
block 2, twelve 4K blocks per track) whose partition is a natively built ext2
image (`filesystem.ext4_build(..., ext2 = True)`); the initramfs loads
`dasd_mod`, `dasd_eckd_mod` and `ext2` from the kernel package with Debian 7's
static BusyBox and switches root to `/dev/dasda1`, and the guest's writes go to
the DASD overlay. `scripts/inspect/linux_s390.star [dasd]` steps either boot
with symbol lookup from the kernel's `System.map`.

```starlark
m = emulator.s390(memory = 256 << 20, start = "2003-11-01T12:00:00Z")
m.dasd(0x0200, volume_file)          # CKD_P370 or compressed CKD_C370
m.console(0x0320, rows = 24, cols = 80)
m.ipl(0x0200, loadparm = "0320")
r = m.run(instructions = 50000000)   # r.kind: budget, idle, disabled-wait, ...
print(m.screen(0x0320))
m.type(0x0320, "LOGON MAINT")
m.key(0x0320, "ENTER")
write("console.png", m.screenshot(0x0320))
```

A load from storage-resident images replaces the IPL channel program, as the
service processor's load from removable media or a server does; the operating
system then talks to the hardware system console:

```starlark
m.storage_load([(0, kernel), (0x800000, initrd), (0x10480, "root=/dev/ram0\0")])
m.run(instructions = 100000000)
print("\n".join(m.messages()))       # operating system messages
m.command("uname -a")                 # operator command
write("console.png", m.screenshot())  # hardware console without a device
```

## System/370

`emulator.s390(architecture = "s370")` runs the System/370 architecture on
the same CPU: BC- and EC-mode PSWs (in BC mode interruption codes live only in
the old PSW, and the PSA locations stay ordinary storage), System/370 DAT with
2K or 4K pages, 64K or 1M segments and two-byte page-table entries, storage
keys per 2K block (SSK, ISK, RRB), the interval timer at location 80, and
channel I/O through START I/O, TEST I/O, HALT I/O, TEST CHANNEL and STORE
CHANNEL ID with the CAW and CSW. Storage is limited to 64M.

```
go run ./cmd/trex scripts/smoke/vm370.star OUT ESSENTIALS.tar.gz VMREL6.ddr.aws.bz2 CPR6L0.ddr.aws.bz2
```

installs the public-domain VM/370 Release 6 starter system the way its
instructions describe: stand-alone DDR is IPLed from tape and restores both
DDR tapes onto newly initialized 3330s, CP is IPLed and cold started, MAINT
logs on at a 3277 and IPLs CMS, and CMS lists its S disk. It takes about 20
seconds, most of it reading the bzip2-compressed tapes.

```
go run ./cmd/trex scripts/smoke/mvs38j.star OUT
```

IPLs public-domain MVS 3.8j from the pinned Turnkey 3 media
(`scripts/images/mvs38j_turnkey.star`; the 512 MB zip is cached once and its
compressed CKD volumes are read in place from the ISO). NIP is answered on
the 3270 master console, JES2 is cold started and formats its spool, and an
IEBGENER job submitted through the card reader runs and prints its SYSIN line
on the 1403. VTAM then puts its logon screen on the local 3277 at 0C0 and
IBMUSER logs on to TSO and runs TIME. About 9 seconds and 150 million
instructions. The Turnkey's year-2000 changes display the 1985 clock as 2085. `scripts/inspect/mvs38j_ipl.star` and `vm370_install.star` step
these systems (steps are listed in `scripts/inspect/s370_steps.star`).

Channel behaviour these systems depend on: a CCW with the PCI flag pauses
the channel program and presents a program-controlled interruption (in
ESA/390 mode as intermediate status that TEST SUBCHANNEL clears while the
subchannel stays active, keeping the ORB's CCW-format bit in the SCSW for
the final status, from which an I/O supervisor may choose how to redrive
the program), and the program continues after the CPU has handled it (MVS
program fetch and JES2 rewrite CCWs that way); on 3330/3350 control units the file mask's
seek-control bits inhibit multitrack operations (IPL and fetch recover from
the resulting file-protect check at a track boundary), while on a 3990 a
multitrack operation under Define Extent continues onto the next track and
cylinder, as the architecture of Define Extent permits; within a data chain the skip flag and the
CSW count and address belong to the individual CCW.

Devices for these systems: `m.console(dev, type = "3215")` (line-mode
console whose reads wait for `m.type`), `m.unit_record(dev, type = "2540R",
cards = [...])` for readers, punches and printers (`m.cards(dev, [...])`
readies a reader with a new deck, `m.output(dev)` returns punched or
printed lines),
`m.tape(dev, file)` for a 3420 with an AWS image, and `m.dasd(dev, file)` for
CKD images of 3390, 3380, 3375, 3350, 3340, 3330 and 2314 volumes, or
`m.dasd(dev, type = "3330", cylinders = 404, volser = "VMREL6")` for a newly
initialized empty volume.

## Time

Virtual time advances with executed instructions at the configured `mips`.
When every CPU is in an enabled wait, time jumps to the next timer deadline. A
CPU that executes thousands of instructions with interruptions enabled while
storing nothing and reading no clock is in a polling loop that only an
interruption can end; time also jumps to the next deadline there
(`idle_skip = False` disables this). Skipped time counts against the
`run(instructions=)` budget at the nominal rate, so a budget is a bound on
virtual time regardless of how much was skipped.

The TOD clock advances with every instruction, so clock reads and timers
stored mid-batch are exact and runs do not depend on how execution is
sliced (a resumed checkpoint ends exactly as an uninterrupted run).

## Observation

`messages()`, `registers()`, `psw()`, `read()`, `find()`, `disassemble(virtual=)`
(primary virtual addresses when `virtual` is set), `events()`
(IPL, program interruptions, SIE exits, SERVC, SCK and, with `trace_io(skip=)`,
each START SUBCHANNEL with its CCWs, flags and status, leaving out the devices
in `skip`), `history(keep=, guest=)`, `break_at()`, `break_program(code)`
(stop when a program interruption with that code is taken, registers intact),
`watch()` for stores overlapping an absolute range, `profile()` by
instruction address, `interrupts()` including SIE exit codes, and
`dasd_errors()`.

## DASD sense

Unit-check sense marks bytes 0-23 as the 24-byte compatibility format
(byte 27 bit 0), as the 3990 reference describes; without it, error
recovery cannot interpret the sense and may retry every unit check. A
locate-record domain that would leave the defined extent ends with a
file-protect check, which access methods take as the end of the extent (and,
on the last one, of the data).
